# 代码审查检查单（双轴）

`ss-code-review` 依据本单执行。两轴独立评分，任一轴出现 BLOCKING 即整体 FAIL。

## 轴一：Spec 合规（是否满足需求）

- [ ] 实现覆盖 spec（逻辑名 `spec.md`，由编排器通过 `processing-state/phaseK-complete.md` OUTPUTS 段解析为 `NN-spec.md`）全部验收标准（GWT 逐条对照）？
- [ ] 无超范围实现（未偷加功能/抽象）？
- [ ] 边界与异常场景已处理（空值/越界/并发/失败回滚）？
- [ ] 与 design（`NN-design.md`）的架构/API/DB 约定一致？

## 轴二：Standards 合规（代码质量）

- [ ] 分层正确、职责单一、无跨层违规？
- [ ] 命名清晰、无魔术值、无重复代码？
- [ ] 无明显性能问题（N+1、无界查询、循环内 IO）？
- [ ] 安全：无注入/越权/硬编码密钥/敏感日志？
- [ ] 校验在边界、返回体统一、异常不吞？
- [ ] 有对应测试且覆盖正常+异常路径？
- [ ] 符合 `coding-standards*.md`？

## 问题分级

- **BLOCKING**：功能不正确/安全漏洞/破坏架构 —— 必须改。
- **WARNING**：可维护性/规范偏差 —— 必须改，与 BLOCKING 同等阻断，不可仅记 TODO 放行。
- **NORMAL/建议**：风格偏好 —— 可选。

## 输出

对每条问题给出：文件:行号、级别、问题、建议修复。禁止仅凭作者自述判定通过——必须看 diff 与测试证据。
