# Python SonarQube 规范（3.10+）

## 重要原则

> * 本文件为技术栈规则，执行时严格遵循
> * 新代码优先治理，历史代码逐步改善
> * SonarQube 是质量门禁，不可绕过

---

## 1. 目标定位

SonarQube 在本项目中定位为**质量门禁工具**，重点关注：

- **新增代码零阻断问题**
- **核心模块高覆盖率**
- **安全漏洞零容忍**

---

## 2. 与其他规范的关系

| 规范 | SonarQube 职责 |
|------|---------------|
| code-style.md | SonarQube 检查代码风格违规 |
| testing.md | SonarQube 验证覆盖率达标 |
| project-structure.md | SonarQube 不检查目录结构（由人工审查） |
| 变更安全/命令约束（orchestrator-behavior.md） | SonarQube 不检查（由人工审查） |

---

## 3. 治理策略

### 3.1 优先级

| 优先级 | 目标 | 说明 |
|--------|------|------|
| P0 | 新代码零 Blocker/Critical | 每次提交必须通过 |
| P1 | 覆盖率达标（阈值见 wf-dev.yaml `coverage.*`） | 新代码必须达标 |
| P2 | 历史代码 Major 问题 | 按模块逐步改善 |
| P3 | 历史代码 Minor/Info | 低优先级 |

### 3.2 Quality Gate 配置

| 指标 | 阈值 |
|------|------|
| 新代码 Blocker | 0 |
| 新代码 Critical | 0 |
| 新代码 Security Hotspot | 0 确认 |
| 新代码覆盖率 | 以 wf-dev.yaml `coverage.new_code` 为准（默认 100%） |
| 新代码重复率 | ≤ 3% |

---

## 4. Python 特定 SonarQube 规则

### 4.1 安全相关（Blocker/Critical）

| 规则 ID | 规则 | 说明 |
|---------|------|------|
| S2068 | 硬编码密码/密钥 | 禁止在源码中硬编码密码/JWT Secret |
| S2076 | SQL 注入 | 禁止拼接 SQL，使用参数化查询 |
| S3649 | 未验证的用户输入 | Pydantic 校验所有入参 |
| S5332 | 不安全的 SSL | 禁止禁用 SSL 校验 |
| S6289 | Log 注入 | 日志中不拼接未校验的用户输入 |

### 4.2 代码质量（Critical/Major）

| 规则 ID | 规则 | 说明 |
|---------|------|------|
| S108 | 空 except 块 | 禁止 `except: pass` 或 `except Exception: pass` |
| S1192 | 魔术字符串 | 提取为常量 |
| S1172 | 未使用参数 | 函数参数必须被使用 |
| S1751 | 不可达代码 | 删除不可达分支 |
| S2209 | 未使用变量 | 变量必须被使用 |
| S1854 | 无用赋值 | 变量赋值后未使用 |
| S106 | print 语句 | 使用 logger 替代 print |
| S1135 | TODO/FIXME | 不允许遗留未处理的 TODO |

### 4.3 重复与复杂度

| 规则 ID | 规则 | 说明 |
|---------|------|------|
| S104 | 文件行数过多 | 单文件不超过 500 行 |
| S138 | 函数行数过多 | 函数不超过 50 行 |
| S134 | Cognitive Complexity 过高 | 核心函数不超过 15 |
| S125 | 注释中的代码 | 删除注释中的废弃代码 |

## 5. Python 3.10+ 特定检查

| 规则 | 说明 |
|------|------|
| 使用 `X | Y` 替代 `Union[X, Y]` | 3.10+ 新语法 |
| 使用 `X | None` 替代 `Optional[X]` | 3.10+ 新语法 |
| 使用 f-string 替代 `%s` / `.format()` | 可读性更好 |
| 公开函数必须有类型注解 | 类型安全 |
| 使用 Pydantic 校验入参 | 不手写校验逻辑 |
| 使用 `async def` 异步函数 | FastAPI 异步场景 |

---

## 6. 修复要求

| 问题级别 | 处理方式 | 时间要求 |
|----------|---------|---------|
| Blocker | 必须立即修复 | 当前提交 |
| Critical | 必须修复 | 当前提交 |
| Major | 优先修复 | 本次迭代 |
| Minor | 建议修复 | 后续迭代 |
| Info | 记录 | 有空再处理 |

---

## 7. 扫描范围建议

| 场景 | 扫描范围 |
|------|---------|
| 日常开发 | 仅扫描本次改动的文件 |
| PR Review | 扫描 PR 涉及的所有文件 |
| 质量门禁（ss-test-run） | 扫描全部新增代码 |
| CICD | 全量扫描 |

---

## 8. AI 约束

- AI 生成代码必须符合 SonarQube 新代码零 Blocker/Critical 标准
- AI 不修复与本次任务无关的历史 SonarQube 问题
- AI 可在总结中提示发现的历史问题，但不擅自扩大改动范围

---

## 最终回复要求

* 说明是否有 SonarQube 阻断问题
* 说明覆盖率是否达标
* 说明发现的历史问题（如有，仅提示不修复）
