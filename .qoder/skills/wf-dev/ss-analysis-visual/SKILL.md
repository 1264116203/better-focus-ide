# ss-analysis-visual — 视觉知识提取

**阶段**: analysis | **独立可用**: 可（给定 PRD 路径即可单独产出视觉笔记）| **profile**: basic/enhanced

## 前置条件
- 有 PRD 文件路径 / Confluence 导出的 Markdown（含图片引用）。
- 工作流模式下作为 **Phase 1**（intake 之前）由编排器条件触发调用。

## 配置加载
执行前**必须**使用 Read 工具读取 `.qoder/wf-dev.yaml`，提取：
- `workflow_dir.active` → 产物写入路径（wf-feature-* 使用）
- `slug.*` → slug 格式校验
- `profile.default` → 缺省 profile（basic/enhanced）

工作流模式下 **PRD 文件路径 / PRD_DIR 由编排器上下文传入**；独立调用时从用户 prompt 获取 PRD 路径。未完成配置加载不得开始执行。

## 输入
- `--slug <feature-slug>`（可选，缺省自动生成）
- PRD 来源（文件路径 / Confluence pageId）由编排器上下文或用户 prompt 给出

## 执行步骤

### 步骤 1：扫描 PRD 全量图片/原型引用
使用 Grep 扫描 PRD 文件，**必须同时覆盖以下格式**，合并去重，记录每张图在 PRD 中的行号/所在章节：
- Markdown 图片：`!\[[^\]]*\]\(([^)]+)\)`
- HTML 图片：`<img[^>]+src="([^"]+)"`（Confluence 导出常把图嵌在 `<td>` 内，**极易遗漏，已知高频缺陷**）
- 原型/附件：`<iframe[^>]+src="([^"]+)"`、`\[[^\]]*\]\(([^)]+\.html?)\)`、`<a[^>]+href="([^"]+\.html?)"`

> **无命中 → 写跳过产物**：写 `visual-notes.md`，内容注明跳过原因"PRD 无图片/原型引用"，由编排器 resolver 重命名为 `01-visual-notes.md` 并写 `phase1-complete.md`。不阻断、不报错。

### 步骤 2：多模态能力检测（降级跳过）
以最小代价探测运行模型是否支持读图：尝试用 Read 读取扫描到的**首张图片**。
- 若返回"不支持图片/多模态"类错误（无法解析图像输入）→ 判定不具备多模态能力：
  - 标 **WARNING**，写 `visual-notes.md`，内容注明跳过原因"运行模型不支持多模态，图片语义未提取；如需视觉提取请切换支持多模态的模型后重跑（可配合 --resume）"。
  - 由编排器 resolver 重命名为 `01-visual-notes.md` 并写 `phase1-complete.md`。结束。
- 与"无图跳过"同级处理，绝不因多模态缺失中断工作流。

### 步骤 3：逐图判类型
对每张图用 Read（多模态）**先判类型**：`业务流程图` / `技术时序图` / `架构图` / `UI 界面(Web/App/小程序)` / `其他`。类型不明确时归入 `其他` 并标注"类型未识别，建议人工确认"。

### 步骤 4：按类型结构化提取（schema 见下）
逐项提取，识别不清的项打 `⚠️待确认` 标记，**禁止臆测填充**（防幻觉）。

| 图片类型 | 提取的结构化内容 |
|---|---|
| 业务流程图 | 参与角色、步骤序列、判定分支与条件、异常/回退路径、起止点 |
| 技术时序图 | 参与者、按序调用/消息、同步/异步、返回值、alt/loop 片段 |
| 架构图 | 组件/服务、分层、依赖与数据流方向、协议、外部系统、数据存储 |
| UI 界面(Web/App/小程序) | 页面名、布局区域、组件、字段(名/类型/必填/校验/默认)、交互事件、页面状态(空/加载/错误)、导航跳转、**多端差异** |
| 其他/未分类 | 兜底通用描述 + 标注"类型未识别，建议人工确认" |

### 步骤 5：验证原图链接可达，并按产物位置重写
对每张图的原始引用先解析为**绝对路径**，用 Bash `test -f <绝对路径>` 验证文件存在（外部 URL 只校验格式合法，不 `test -f`、不下载）。不可达 → 标 WARNING，仍保留引用并在图注注明"路径不可达"。

**链接基准重写（强制）**：产物最终目录与 PRD 目录通常不同（如 PRD 在 `requirements/active/<sprint>/<feature>/`，产物在 `technologies/active/<sprint>/<feature>/processing-state/`），直接照抄 PRD 内的相对路径（如 `attachments/xxx.png`）会导致链接失效。必须：
- 用步骤 7 确定的产物所在目录为基准，用 `realpath --relative-to=<产物目录> <图片绝对路径>`（或等价 Python `os.path.relpath`）换算相对路径；
- 写入的链接**只允许**两种形态：① 相对产物目录的合法相对路径；② 外部 URL。禁止把 PRD 目录基准的相对路径原样写入；
- 独立调用写当前工作目录时同样按"产物目录基准"重写，不豁免。

### 步骤 6：汇总存疑点清单
收集所有 `⚠️待确认` 项，集中写入「存疑点清单」章节，每条格式 `- [ ] 图N：<存疑点描述>`，供 intake 直接消费提问。

### 步骤 7：写产物
写逻辑名 `visual-notes.md`（**禁止自己加 `NN-` 前缀**，由编排器 resolver 加 `00-`）。路径规则：wf-feature-* 写 WORKFLOW_DIR 根目录；wf-prd-split 写 `PRD_DIR/processing-state/`；独立调用写当前工作目录。结构见「输出格式」。

## 输出格式：visual-notes.md

```markdown
# 视觉知识笔记（visual-notes）

## 元信息
| 字段 | 值 |
|------|-----|
| PRD 来源 | [<PRD 标题>](<相对本产物所在目录的路径或 URL>) |
| 图片总数 | <N> |
| profile | <basic / enhanced> |

## 图片索引
| # | 图片链接 | 类型 | PRD 中位置 | 提取章节指代 | 置信度 |
|---|---------|------|-----------|-------------|--------|
| 1 | ![](../../../../requirements/active/sprint2610/PRD.../attachments/x.png) | 业务流程图 | §3.2 / L120 | §图1 | 高/中/低 |

<!-- 图片链接一律为"相对本产物所在目录"的路径（步骤 5 重写结果）或外部 URL，禁止照抄 PRD 目录基准的相对路径 -->

## 逐图结构化提取
### 图1：<标题>（<类型>）
- 原图：![<描述>](<相对本产物所在目录的路径，经 test -f 验证>)
- <按步骤 4 对应 schema 的结构化提取内容>
- ⚠️待确认：<识别不清的点>

## 存疑点清单（供 intake 提问）
- [ ] 图1：<存疑点描述>
- [ ] 图3：<存疑点描述>
```

### 步骤 8：写产物后链接自检
`visual-notes.md` 写完后，从**产物所在目录**逐条提取图片链接做 `test -f` 复检（相对路径以产物目录为基准拼接）：
- 发现失效链接 → 按步骤 5 规则修正后**重写产物**，再次自检，直至全部可达。
- 外部 URL 不参与复检。

## 完成标准 (Done)
- PRD 含图且模型支持多模态时：`visual-notes.md` 已写出，含全部四段（元信息 / 图片索引 / 逐图提取 / 存疑点清单）。
- 每张相关图片均已判类型并按对应 schema 提取；原图链接经 `test -f` 验证（或注明不可达 WARNING）。
- 产物内**所有**图片链接均已按产物所在目录重写，步骤 8 自检通过（0 失效链接）。
- 识别不清项均以 `⚠️待确认` 标记并汇入存疑点清单，无臆测填充。
- PRD 无图 或 模型不支持多模态：写 `visual-notes.md`（注明跳过原因），由编排器 resolver 重命名并写 `phase1-complete.md`，不阻断。

## basic vs enhanced
- **basic**：只完整提取 `业务流程图` + `UI 界面` 两类（最影响需求理解），其余类型仅保留链接 + 一句话摘要；存疑点清单仅列阻断性项。
- **enhanced**：全类型完整提取 + 完整存疑点清单（含低置信度项）；UI 图强制标注 Web/App/小程序 多端差异。

## 异常处理
- PRD 文件不可读 → 标 BLOCKING，回退用户补充 PRD 路径。
- 运行模型不支持多模态 → 标 WARNING 并静默跳过（见步骤 2），不阻断。
- 图片路径不可达 → 标 WARNING，保留引用并注明，继续处理其余图片。
