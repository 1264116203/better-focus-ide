## 修复：提问卡片不主动弹出 + 图钉（置顶）逻辑失效

**现象**：`question_requested` 到达后卡片只更新气泡计数，需手动点气泡才展开；点图钉除图标换色外没有任何行为变化。

**日志证据**（`~/Library/Application Support/BetterFocusIDE/logs/betterfocus.log`）：
00:15:53 收到 question_requested，直到 00:17:40 才有 `animateTo ... activeCard=question`；
期间 `pinned=false`。00:18:48/49 两次 togglePin 后无任何 animateTo；随后出现多组
`collapse → 0.1s 后 expand` 的成对记录。

**根因**：
1. `NotchService.showCard` 把「是否主动展开」绑定在 `pinned` 上，按需模式（pinByDefault=false
   或 userPinned=false）下交互式卡片只静默排队等悬停；而 hook 是阻塞等待回答的，超时即回落 IDE。
2. `mouseExited` 排除了 question/permission，且这些卡片从不会自动收起 → pinned 对它们完全无效果。
3. `userPinned` 一旦被手动设置就永久覆盖设置面板的 pinByDefault，开关失效。
4. `collapse()` 只在 pinned 时记录让位期，按需模式下悬停状态机立刻重开，卡片反复闪烁。
5. `NotchView` 展开态气泡与外层各挂一个 onTapGesture，同一次点击触发 collapse+toggle→expand。

**改动**（3 个文件）：
- `Services/NotchService.swift`：交互式卡片到达无条件主动弹出一次，pinned 只决定「展开后是否保持」；
  pinned 初值同步 `Settings.shared.pinByDefault`；mouseExited 对交互式卡片也安排延迟收起；
  togglePin 后即时展开/收起；设置面板改 pinByDefault 时清 userPinned；collapse 无条件记录让位期，
  并新增 manualCollapseNeedsMouseExit 防止鼠标未移出就自动重开；新增 `topic: "card"` 日志。
- `UI/NotchView.swift`：合并为单个带落点坐标的 onTapGesture，展开态仅顶部气泡区域可收起。
- `Services/SettingCatalog.swift`：更新 pinByDefault 的说明文案。

**验证**：`swift build -c debug` 通过（无警告），`./build.sh` 组装签名成功。
`swift test` 26 例中 4 例失败，均为 `SettingsTests` 里 `SettingCatalog.byKey("bodyFont")` 找不到定义——
HEAD 版本的 SettingCatalog 同样没有 bodyFont，属既有失败，与本次改动无关。

**注意**：工作区同期还有一批 Cursor / WorkBuddy hook 接入的未提交改动（AgentProvider、
IDEIconProvider、IDELauncher、InstallerPaths、Settings，以及 3 个新增 Installer 文件），
非本次修复内容；构建时已一并编译通过。

## 完成：Cursor / WorkBuddy 事件源适配（commit 836ea62 + 85c4788）

**架构**：四个宿主（Qoder / OpenCode / Cursor / WorkBuddy）走同一条 Unix socket，
差异只在安装目标与事件方言：

| 宿主 | 配置文件 | 事件方言 | 能力 |
|------|----------|----------|------|
| Cursor | `~/.cursor/hooks.json`（version:1） | camelCase `stop`/`sessionEnd` | 仅观测，恒回 `{}` |
| WorkBuddy | `~/.workbuddy/settings.json` 的 `hooks` | PascalCase，Claude 同构 | 提问可回灌答案，权限只提醒 |

**关键决策**：
- Cursor 权限类 hook（`preToolUse`/`beforeShellExecution`）必须回 allow/deny，回非法 JSON
  直接阻塞工具调用 → 只注册观测型事件，绝不接管审批。
- WorkBuddy `Notification`（matcher `permission_prompt`）与 `PermissionRequest` 双路
  观测，权限事件 **stdout 保持静默**（不 emit decision），保留宿主原生对话框。
- 提问仍走 `PreToolUse` + `AskUserQuestion` 阻塞式 hook，岛上答案通过 `deny` 的
  reason 回灌给 Agent（Qoder 已验证的通道，WorkBuddy 同构可复用）。
- `HostHookTemplate.swift` 一份 Python 正文 + `EVENT_STYLE` 分流，占位符在安装时替换。
- 设置面板写回改为**只刷新已安装的集成**（`isInstalled`），避免无端改写 WorkBuddy
  存有账号信息的 settings.json；写回后状态行列出实际刷新的宿主。

**验证**：`swift build`、`swift test`（26 例全绿）、`./build.sh` 打包签名均通过；
`/tmp/bf_hook_protocol_test.py` 从 Swift 源码抽取模板、用假 socket 驱动，14 项协议
断言全通过（两种方言的 turn_finished / session_ended / 提问回灌 / 权限静默）。

**注意**：`swift build` 在本机需加 `--disable-sandbox`（SwiftPM 二次沙盒与当前环境冲突）；
跑 `build.sh` 时用 `/tmp/bf-shim/swift` 包装脚本注入该参数。

## 卡片 IDE 图标统一尺寸（commit 7c4267）

**问题**：四类卡片各用各的尺寸（提问 24 / 通知 28 / 权限 28 / 历史 24），且图标 PNG
自带留白差异巨大。实测内容包围盒：JetBrains 全家桶 1.00（满画布）、Cursor 0.803、
WorkBuddy 0.801、iTerm/Warp 0.820、Qoder 0.773 → 同框渲染视觉大小差 ~25%。

**改法**：
- `IDEIconProvider.badgeSize = 30` 作为唯一尺寸常量，四处调用点全部引用（历史面板的
  宽度公式也用它，否则标题区会多算 6pt）。
- `loadImage` 加载后统一 `trimmed()` 裁到不透明包围盒：先在 64×64 缩略图上粗测
  （阈值 alpha>24 滤抗锯齿），再映射回原图 `CGImage.cropping`；满画布的图标直接
  原样返回省一次重采样。结果按名字缓存（NSLock 防御）。
- 文字徽章的圆角 `size*0.22`、字号 `size*0.42` 随 size 等比，不再写死 6 / 12。

**验证**：`IDEIconProviderTests` 三条——裁切后包围盒 ≥0.97、`ImageRenderer` 以 30pt@2x
离屏渲染后每个图标长边 ≥58/60px、名称/bundle 匹配不变。测试总数 33 → 36 全绿。
实机截图测量：通知卡 WorkBuddy 图标 34×33.5pt（30pt × 铃铛摆动 scaleEffect ≈1.13）。

**坑**：`screencapture -R` 的坐标是点、输出是像素（2x）；副屏抓不到内建屏的刘海面板，
要先全屏截图确认面板在哪个屏。权限/通知横幅 5s 自动收起，抓图要卡在事件后 1s 左右。
