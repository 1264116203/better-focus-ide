# 「一道题问两遍」在其它宿主上是否同样存在

排查对象：所有已接入的宿主，看它们的提问工具会不会在 hook 返回**之前**就把
自己的问卷面板画出来——若是，岛上再弹一张卡就是同一道题问两遍。

判定规则（`Services/QuestionTakeover.swift`）：**默认一律由岛接管（岛优先）**。

> 定稿前的弯路：第一版是「GUI 宿主在前台就让位给它的原生面板」。实测 WorkBuddy
> 后否掉了——宿主面板在 hook 返回**之前**就画好了，hook 拦不住；让位的唯一效果是
> 岛上不弹卡，而用户在 IDE 里那次作答仍会被 deny 丢掉。等于把唯一有效的入口关掉。
> 现在的策略：岛必弹、答案以岛为准，宿主面板成为「看得见但不算数」的残影。
> `Policy.deferToHostWhenFrontmost` 只作为可选开关保留，启用前必须先证伪上面这条。

## 一、逐宿主结论

| 宿主 | 形态 | 提问通道 | 会不会双份 | 现行行为 |
|---|---|---|---|---|
| WorkBuddy | macOS GUI | `PreToolUse(AskUserQuestion)` | **会（已实测）** | 岛接管（宿主面板成残影） |
| Qoder / Qoder CN | GUI（含 IDEA 插件） | `PreToolUse(matcher *)` + helper | 同构，**待实测** | 岛接管 |
| Trae / Trae CN | VS Code 系 GUI | `PreToolUse(AskUserQuestion)` | 同构，**待实测** | 岛接管 |
| Claude Code | 终端 | `PreToolUse(AskUserQuestion)` | 不会 | 恒接管 |
| Kimi Code CLI | 终端 | `PreToolUse(AskUserQuestion)` | 不会 | 恒接管 |
| Qoder CLI | 终端 | 同 Qoder helper | 不会 | 恒接管 |
| OpenCode（TUI） | 终端 | 插件接管 `question` 工具 | 不会（原生表单已被插件替换） | 恒接管 |
| OpenCode（`serve` + 浏览器） | 浏览器 | 同上 | 不会（同上，Web 端拿不到 pending 表单项） | 恒接管 |
| Cursor | GUI | hook 枚举里**没有**提问位 | 不涉及 | 拿不到事件 |
| Codex | 终端 TUI | 自审、无事件 | 不涉及 | 拿不到事件 |

终端宿主与浏览器会话在「岛优先」下同样由岛接管，只是它们压根不会出现第二份：
`deny` 在工具执行前生效，终端来不及画；插件接管 `question` 工具时原生表单没被执行，
Web/TUI 端无从渲染。唯一看得到残影的是「工具已经跑起来、宿主边跑边画」的 GUI 面板。

## 二、顺带发现的真问题：老脚本读不懂让位信号（协议仍保留）

让位是**跨进程协议**（`answer_index = -4` / `defer: true`）。发出让位的是岛，
读懂它的是各宿主的脚本副本——副本没跟着刷新，就会把 `-4` 当成未知下标，
提问卡在那里直到超时，比原来的「问两遍」更糟。

实测本机（修复前）：`~/.trae/hooks/…` 还是装机那天的 04:36 版本，`~/.claude`、
`~/.kimi-code` 同理，都没有 defer 分支。原因是启动自愈
（`NotchService.repairInstalledIntegrations`）只覆盖了 OpenCode / Qoder /
Cursor / WorkBuddy / Qoder CN。

修法：自愈扩到 Claude Code、Trae（国际/国内）、Kimi、Codex。重启后八份脚本
全部含 defer 分支，`ast.parse` 全过；OpenCode 插件 `node --check` 过。

## 三、怎么自测某个宿主

1. 让该宿主处于**前台**，触发一次提问（IDE 里让它问你一个问题）。
2. 期望：**岛上弹卡**，日志 `card: showCard: question 主动弹出`、且**没有**
   `question: 让位…` 记录。宿主那边可能仍显示一份问卷残影，在岛上作答后它自行收起。
3. 在岛上选完，确认 IDE 里的工具结果就是岛上那次选择（没有被"再问一遍"）。
4. 若出现「岛上选完、IDE 又让人选一遍」→ 说明该宿主的工具没有走我们 hook 的
   deny 回灌，需要看它的 hook 方言是否支持 `permissionDecision.reason` 作为工具结果。

若哪天要退回「让位给宿主」，把 `QuestionTakeover.shouldTakeOver` 的 `policy` 传成
`.deferToHostWhenFrontmost` 即可——前提是先证明该宿主的面板能在 hook 返回前
**独立完成作答**，否则问题会被晾到超时。
