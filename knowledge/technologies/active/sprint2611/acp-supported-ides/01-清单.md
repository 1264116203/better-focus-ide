# 支持的 IDE 清单

日期：2026-11-10

安装菜单和引导页的勾选顺序以 `HookInstallCatalog.all` 为准。本机没装的项不会出现在右键安装菜单里。配置目录不存在时，安装器会自己建。

「作答」是在岛上选完，答案写回宿主。「提醒」只出横幅，批准或作答仍在宿主自己的界面里。「—」是这个宿主的事件里没有这一项。

Qoder 的桌面版、IDE、CLI 和 JetBrains 插件共用能力那一行。国内版写在 `~/.qoder-cn`，靠 `BETTERFOCUS_VARIANT=cn` 与英文版分开。改完 hook 要重启对应 IDE 才生效。

## 和表上字面不一样的地方

- **Cursor** 的权限只提醒。终端命令和 MCP 调用会在岛上亮一条通知，点一下跳回去，批准仍在 Cursor 自己的对话框里。没有提问卡，也没有待办。读文件和通用工具调用不接。
- **WorkBuddy** 的提问不在岛上作答。宿主自己的问卷会先出现，岛上只亮一条提醒。权限同样只提醒。`settings.json` 改完不会热加载，要重开当前会话。
- **Trae / Trae CN** 没有会话结束事件。待办在对话里看得到，hook 收不到，所以没有进度卡。
- **ChatGPT**（原 Codex）的工具名里没有 `AskUserQuestion`，也没有能对上的待办事件。装好之后还要在 ChatGPT 里把 hook 信任一次，改过脚本要重新信任。`notify` 已被别的程序占用时跳过这一键，`hooks.json` 照常登记。
- **OpenCode** 没有权限提醒，也没有会话结束。

部分宿主还会多几张横幅：子任务完成、文档或浏览器待审、上下文即将压缩或已经压缩、这一轮没有完成、额度或登录失效。点一下同样跳回原来的窗口。工具调用失败不通知。

## ACP 会话

勾选「JetBrains ACP」之后，`installed.json` 里本机平台的 `cmd` 换成 `acp-bridge.py`，原来的命令记在 `~/Library/Application Support/BetterFocusIDE/acp-bridge.json`。登记里的相对路径（`./dist-package/cursor-agent`）在启动时按 `~/Library/Caches/JetBrains/<IDE>/acp-agents/<名字>/<版本>/` 解析成绝对路径。IDE 更新代理把命令盖回去之后，下次打开 BetterFocusIDE 会再套一次。当前已经开着的会话要重开才走桥。

桥只转发 JSON-RPC，不代答。能亮的和上面这张表里「提醒」那一档一样：

| 岛上的事件 | ACP 来源 |
|---|---|
| 回合完成 | `session/prompt` 之后的 `state_update` idle，或响应里的 `stopReason` |
| 权限提醒 | `session/request_permission` |
| 提问提醒 | 同上，工具名是 `AskUserQuestion` |
| 待办 | `plan_update` 整表；`TodoWrite` / `TaskCreate` / `TaskUpdate` 的 `rawInput` |
| 会话结束 | `session/close`，或桥进程退出 |

点卡片看桥报上来的 `host.bundle`（外面那个 IDE）和 `session/new` 的 `cwd`。JetBrains 因此走到项目窗口。代理自己的 hook 若还在跑，看到 `BETTERFOCUS_ACP_BRIDGE=1` 就不再往岛上发，避免同一轮两张卡片。

安装时从 app 包里读出 `acp-bridge.py` 再写到 Application Support。SwiftPM 把它放在 `BetterFocusIDE_BetterFocusIDE.bundle/Contents/Resources/acp-bridge.py`，不在资源包根目录。`AcpBridgeInstaller.scriptText(in:)` 先查这一层，再用 `Bundle.url(forResource:)`，最后才看包根。编译进二进制的源码路径只在开发机上存在，不能当发行包的查找路径。脚本没写出去时，自检会同时报「Hook 脚本：未安装」和「Hook 开关：未在宿主配置中登记」——安装在 `loadSource()` 就失败了，登记也不会改。

Qoder 自检认 `settings.json` 里的 command，不单认 `_betterfocus_marker`。Qoder 重写配置时会丢掉这个自定义字段，命令还在就仍算已登记。
