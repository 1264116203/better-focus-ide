# 宿主卡片兼容性

日期：2026-11-07

这份记录回答两件事：各宿主官方文档里**有哪些 hook / 插件事件**，以及 BetterFocusIDE **实际登记了哪些**、因此能弹出哪几张卡片。官方有、我们没挂的，单独写在「没做」里，避免以后把「文档里有」误当成「岛上会出」。

卡片本身只有这几张，和宿主无关的历史面板不算在内：

| 卡片 | 岛上的事件 | 用户能做什么 |
|---|---|---|
| 提问 | `question_requested` | 在岛上作答，答案写回宿主 |
| 权限提醒 | `permission_notice` | 只看横幅。审批仍在宿主自己的对话框里 |
| 回合完成 | `turn_finished` | 看横幅，点一下跳回那个窗口 |
| 会话结束 | `session_ended` | 同上，会话关掉时再亮一次 |
| 待办 | `todo_updated` / `todo_item_updated` | 进度条，不是一张独立卡片 |

`UserPromptSubmit` 不单独出卡。它只把用户刚打的那句话记下来，给后面的回合完成横幅当标题。

「能出」指本项目安装器**已经登记**、脚本也认的能力。「官方有、我们没挂」见下一节。

## 各宿主

### Qoder / Qoder CN

IDE / JetBrains 插件目前支持 12 个事件，其中 `PreToolUse`、`PermissionRequest`、`Stop` 可以阻断，`SessionEnd` 和 `Notification` 不能。CLI 的事件更多（含 `TaskCreated` / `TaskCompleted`），配置文件和 IDE 共用 `~/.qoder/settings.json`，但**改完不会热加载**，要重启 IDE。

我们登记的是 `PreToolUse(*)`、`PermissionRequest(*)`、`PostToolUse`（todo 家族）、`Stop`、`SessionEnd`。提问走 `PermissionRequest`：这条会等 hook 返回，岛上的答案用 deny + reason 灌回去，宿主自己的问卷来不及出现。其他权限只发提醒，stdout 保持空，原生对话框继续问。

Qoder CN 同一套事件，目录换成 `~/.qoder-cn`。`~/.qoder-cn` 若是指向 `~/.qoder` 的软链，自检不把它算成第二个宿主。

### OpenCode

官方插件事件里和回合有关的是 `session.idle`、`session.status`（`session.idle` 已标废弃，但仍会发）。没有 Claude 那种 `PermissionRequest`。

插件做了三件事：

- 包住 `question` 工具的 `execute`，所以有提问卡
- 包住 `todowrite` / `TodoWrite` / `SetTodoList`，所以有待办
- 订阅 `session.execution.succeeded`（2.2.x 实测）、以及旧版的 `session.idle` / `session.status`，所以有回合完成

没有权限提醒，也没有会话结束。`session.execution.succeeded` 不在这次读到的官方事件列表里，是对着 2.2.5 的行为留的兼容。

### Cursor

[Hooks](https://cursor.com/docs/hooks) 的 Agent 事件包括 `preToolUse`、`beforeShellExecution`、`stop`、`sessionEnd` 等。`preToolUse` 可以 allow / deny。第三方映射表明确写了：Claude 的 `Notification` 和 `PermissionRequest` **没有**对应事件。

我们只登记 `stop` 和 `sessionEnd`，并且恒回 `{}`。原因：权限类 hook 必须给出 allow 或 deny，前者等于替用户放行，后者等于替用户拒绝，非法 JSON 还会把工具调用卡住。所以没有提问卡、没有权限提醒、没有待办。

### WorkBuddy

配置在 `~/.workbuddy/settings.json` 的 `hooks` 字段，协议和 Claude Code 同构（PascalCase、`hookSpecificOutput.permissionDecision`）。公开检索没有找到一份标题就是 WorkBuddy、路径就是 `~/.workbuddy` 的 hooks 专页。最接近的官方说明是腾讯云代码助手 CodeBuddy 的 [Hooks reference](https://www.codebuddy.ai/docs/cli/hooks)（27+ 事件，含 `PreToolUse` / `PermissionRequest` / `Notification` / `Stop` / `SessionEnd`）。安装器按这套协议登记，并注明 settings 改动不会热生效，要重启会话或到 `/hooks` 面板确认。

实际登记：`PreToolUse(AskUserQuestion)`、`Notification(permission_prompt)`、`PermissionRequest`、`PostToolUse`（todo）、`UserPromptSubmit`、`Stop`、`SessionEnd`。提问可以回灌；权限两条都只提醒，重复横幅由岛侧去抖。

### Claude Code

[Hooks reference](https://code.claude.com/docs/en/hooks) 的事件表包含 `PreToolUse`、`PermissionRequest`、`Notification`（matcher 看 `notification_type`，其中有 `permission_prompt`）、`PostToolUse`、`UserPromptSubmit`、`Stop`、`SessionEnd`。`PreToolUse` / `PermissionRequest` 的 matcher 匹配工具名。

我们登记的就是上面这七个里除了「全量工具」以外的子集：提问只匹配 `AskUserQuestion`，权限是 `PermissionRequest` 加 `Notification(permission_prompt)`，待办匹配 `TodoWrite|todo_write|todowrite|SetTodoList|TaskCreate|TaskUpdate`。权限不回 allow，避免绕过审批。

### Trae / Trae CN

[Hook 配置详解](https://docs.trae.cn/ide_hook-configuration-reference) 列出的事件是 `SessionStart`、`UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop`、`Notification`。没有 `SessionEnd`，也没有 `PermissionRequest`。`Notification` 的 matcher 匹配 `notification_type`，不是工具名；取值包括 `permission_prompt`、`ask_user_question`，任务完成是 `idle_prompt`。配置要带 `"version": 1`。国内版文件在 `~/.trae-cn/hooks.json`，国际版在 `~/.trae/hooks.json`。

我们登记 `PreToolUse(AskUserQuestion)`、`Notification(permission_prompt|ask_user_question|document_review|browser_interaction|idle_prompt)`、`UserPromptSubmit`、`Stop`。所以有提问、权限提醒、回合完成。没有会话结束。

**进度卡不能出，2026-11-07 实测确认。** 子智能体工具表里有 `TodoWrite`，对话里也能看到任务清单，但进度卡靠 `PostToolUse` 把整张待办表转发过来。官方「PreToolUse 和 PostToolUse 事件支持的工具」是穷举，只有 `Read` / `Write` / `Edit` / `Glob` / `Grep` / `LS` / `RunCommand` / `WebSearch` / `WebFetch` / `AskUserQuestion` / `Skill` / `mcp__*`，没有 `TodoWrite`，也没有 `TaskCreate` / `TaskUpdate`。本机 `Trae.app` 的 hook 适配层同样只有 `read` / `write` / `search` / `web` / `mcp` / `ask_user_question` / `apply_patch`，没有待办。把 `PostToolUse` 挂上也不会收到事件，所以安装器不登记这一条。

### Kimi Code CLI

[Hooks](https://www.kimi.com/code/docs/en/kimi-code-cli/customization/hooks.html) 把规则写成 `~/.kimi-code/config.toml` 的 `[[hooks]]`，**只允许** `event`、`matcher`、`command`、`timeout` 四个字段，多一个整份配置加载失败。`timeout` 范围 1–600 秒。`PreToolUse` 可以阻断；`PermissionRequest` 文档标成不可阻断，正好只用来做提醒。`SessionEnd` 的 matcher 是 `exit` 或 `archive`。

我们六条都登记了：提问、权限提醒、`PostToolUse` 待办、`Stop`、`SessionEnd`，外加 `Notification(permission_prompt)`。超时被夹在 600 秒以内。

### ChatGPT（原 Codex）

桌面应用已改名 ChatGPT，bundle id 仍是 `com.openai.codex`，配置仍在 `~/.codex`。

两条入口互不覆盖：

1. `config.toml` 的 `notify`：一个 argv 数组，只在回合结束时把 JSON 作为**单个参数**传给外部程序（[config reference](https://developers.openai.com/codex/config-reference) 的 `notify`）。它是单值键。本机这份已经被 Computer Use 占用，安装器发现后**跳过**，不改 `config.toml`。
2. `~/.codex/hooks.json`：生命周期 hook，默认开启（`features.hooks`，关掉才写 `hooks = false`）。stdin 收 JSON。事件包括 `PreToolUse`、`PermissionRequest`、`PostToolUse`、`UserPromptSubmit`、`Stop`、`SessionEnd` 等。[Hooks](https://learn.chatgpt.com/docs/hooks) 写明：`SessionEnd` 和 `Interrupt` 的超时上限是 **3 秒**；非托管 hook 必须在 ChatGPT 里按当前定义信任一次，改了脚本要重新信任，未信任的不会跑。

我们登记 `PermissionRequest`（空 stdout，不拍板）、`UserPromptSubmit`、`Stop`、`SessionEnd`（timeout = 3）、`SubagentStop`、`PostCompact`。回合完成走 `Stop`；若 `notify` 槽是空的，会额外写下 notify，作为旧客户端的回合完成入口。

没挂 `PreToolUse`：官方工具名是 `Bash`、`apply_patch` 和 MCP，没有 `AskUserQuestion`。没挂 `PostToolUse`：官方举例的待办工具是 `update_plan`，和 `TodoWrite` 的参数对不上。没挂 `Notification`：事件表里没有这一项。没挂 `StopFailure` / `PostToolUseFailure`：文档的事件表里没有。

自检的「Hook 开关」看的是 `hooks.json`，不再要求 `notify` 必须是我们的。开关文案会提示：要在 ChatGPT 里信任之后才会真正触发。

### GitHub Copilot CLI

[Hooks reference](https://docs.github.com/en/copilot/reference/hooks-reference) 从 `~/.copilot/hooks/*.json` 加载（设了 `COPILOT_HOME` 则改读那里）。事件名可以写 camelCase，也可以写和 VS Code 扩展兼容的 PascalCase。PascalCase 时 `ask_user` 对应 `AskUserQuestion`，`update_todo` 对应 `TodoWrite`。`preToolUse` 的 command hook **失败即拒绝**（fail-closed），超时反而放行。`permissionRequest` 回 `allow` 会跳过用户确认。

因此我们只在 `PreToolUse` 上匹配 `AskUserQuestion`，不挂全量工具。权限用 `PermissionRequest` 和 `Notification`（权限提醒、提问预览、额度与登录失败）。脚本对 allow/ask 什么都不写。`Stop`（文档里的 `agentStop`）、`SessionEnd`、`UserPromptSubmit`、`PostToolUse` 都登记了。另外登记 `ErrorOccurred`、`PostToolUseFailure`、`SubagentStop`、`PreCompact`，只发横幅。五张原有卡片都能出。

待办有两条入口，都只挂在 `PostToolUse`（`PreToolUse` 失败即拒绝，不能把 `sql` 带进去）。旧名是 `update_todo` / `TodoWrite`。2026-11-07 实测当前 CLI 不走这个名字：技能对照表写明 `TodoWrite` = 会话库的 `sql`，表是内置 `todos`（`id` / `title` / `description` / `status`）。`INSERT` 建任务，`UPDATE` 改状态。其它表和 `todo_deps` 不进进度卡。`database` 不是 `session` 的查询也不进。

自检以前要滚过一串「未安装宿主，跳过」才到 Copilot。现在和 ChatGPT 排在一起：脚本、helper、`betterfocus.json` 三行。目录 `~/.copilot` 存在，或 `copilot` 可执行文件在固定路径 / `PATH` 上，都算装过。

## 已实现的追加卡片

四张都是横幅，跟着「回合完成」开关走，点击跳转也用回合跳转开关。不新增设置项，不回 allow/deny。

| 横幅 | 什么时候出 | 哪些宿主会发 |
|---|---|---|
| 失败 / 限额 | 工具失败、回合报错、自动模式拒绝、额度或登录失败 | Claude、WorkBuddy：`StopFailure`、`PermissionDenied`、`PostToolUseFailure`，以及 Notification 里的 `auth_storage_failure` / `quota_*`。Copilot：`ErrorOccurred`、`PostToolUseFailure`。Kimi、Qoder：`PostToolUseFailure`。Cursor：`postToolUseFailure` |
| 子任务完成 | 子代理结束 | Claude、WorkBuddy、ChatGPT、Qoder：`SubagentStop`。Copilot、Cursor：同名事件。Trae、OpenCode、Kimi 文档里没有，不挂 |
| 计划或文档待审 | 文档待审、浏览器在等、MCP 要人输入但题面不在工具参数里 | Trae 的 `document_review` / `browser_interaction`。Claude、WorkBuddy、Copilot、Qoder 的同类 Notification。`elicitation_dialog` / `Elicitation` 能从转录捞到题面时仍走提问卡，捞不到才出「需要你的输入」 |
| 上下文压缩 | 压缩前或压缩后 | Claude、WorkBuddy、ChatGPT、Qoder CLI 语义：`PostCompact` 写「上下文已压缩」。只有压缩前事件的 Cursor、Copilot、Qoder IDE 写「即将压缩上下文」 |

OpenCode 没有这四类事件，不改插件。ChatGPT 的 hook 改过之后，仍要在 ChatGPT 里重新信任一次才会跑。

## 官方有、我们故意没做

| 宿主 | 官方有 | 为什么没挂 |
|---|---|---|
| Cursor | `preToolUse`、`beforeShellExecution` 等可决策事件 | 必须回 allow/deny，回了就替用户做审批 |
| Trae | `PostToolUse`、`SessionStart`、`SessionEnd` | `PostToolUse` 的工具枚举没有 `TodoWrite`，2026-11-07 实测进度卡不会出。`SessionStart` 不出卡。没有 `SessionEnd`。`UserPromptSubmit` 已挂，只给完成横幅提供标题 |
| ChatGPT | `PostToolUse(update_plan)`、`notify`（槽位被占时） | 待办参数形状未知；`notify` 不能覆盖别人的程序 |
| Kimi | `Notification` | matcher 是任务状态 `task.completed`，不是权限或待审类型 |
| OpenCode | `session.deleted` 等 | 没有对应卡片的产品需求，插件没订阅 |

## 自检怎么读这张表

自检只回答「文件在不在、配置里有没有我们的 command」，不回答「这个宿主的产品能力包不包括这张卡」。ChatGPT 三项曾经一直红，是因为旧安装器只写 `notify`，而本机 `notify` 已被 Computer Use 占用，安装直接失败，提示却仍写「一键安装」。现在一键安装写的是 `hooks.json`，`config.toml` 原样不动。
