# Qoder 权限卡片审批经验（Qoder.app / Qoder IDE / JetBrains 插件）

日期：2026-11-12；JetBrains 插件补于 2026-11-14
范围：岛上的权限卡如何替 Qoder 做审批。Qoder IDE、Qoder CLI、JetBrains 里的 Qoder 插件点「始终允许」后，终端、Web 工具、计划智能体如何变成自动执行。IDE 重新打开设置页也不会退回「每次询问」。插件的设置页读的是它自己的语言服务，不读 IDE 的 `User/app.json`。

同目录的 `01-开发计划.md` 是更早的方案（往两份允许列表追加命令名、不改终端模式）。那份计划已经不用。以本文为准。

---

## 1. 桌面版、IDE、JetBrains 插件不是同一条路

| | Qoder.app（`com.qoder.app`，product `qoder` / `qoder_cn`） | Qoder IDE（`com.qoder.ide`，product `qoder_ide` / `qoder_cn_ide`；CLI 同按钮） | JetBrains 里的 Qoder 插件（product `jetbrains_plugin` / `jetbrains_cn_plugin`） |
|---|---|---|---|
| 卡片挂在哪 | `PreToolUse`。宿主会等 hook 返回，原生审批框还没画出来 | `PermissionRequest`。`PreToolUse` 不等待 | 同一套 Qoder hook 的 `PermissionRequest` |
| 中间按钮 | 「本会话允许」 | 「始终允许」 | 「始终允许」 |
| 记住什么 | 当前会话的 `命令名:*`，会话结束失效 | 终端改为完全访问，Web 工具改为自动执行，计划智能体改为自动运行 | 和 IDE 同一套枚举，写进插件自己的语言服务 |
| 写不写配置文件 | 不写。写进 `~/.qoder/settings.json` 的 `permissions.allow` 会永久作用于整个 Qoder，设置页没有地方改回去 | 写语言服务，并写设置页真正读取的 `User/app.json` | 不写 IDE 的 `User/app.json` 和 `User/settings.json`。插件设置页读 `config/getGlobal` |

应答文件里的决策值仍是 `once` / `always` / `reject`。按钮文案由 `PermissionDecisionValue.buttonLabel(for:)` 按产品换，不改 raw value。

会话模式 `auto`、`bypass_permissions`、`yolo` 不开卡，也不回决策，让 Qoder 自己放行。`accept_edits`（每次询问）仍然开卡。这是智能体会话模式，和设置页的终端模式不是同一个字段。

## 2. stdout 两边不能写成一样

Qoder 会采信 `allow` / `deny`。stdout 没有「始终允许」这种决策。

IDE 的 `PermissionRequest` 只认这三个字段：`hookEventName`、`permissionDecision`、`permissionDecisionReason`。多附一个 `decision.behavior`，解析器报 `winner=none (no parsed output)`，整段 stdout 丢掉，卡片上的允许不生效，IDE 接着弹出自己的选择框。`decision` 只在 `_desktop_qoder()` 为真时附上。

Qoder.app 需要 `hookSpecificOutput.decision.behavior`（只有 `allow` / `deny`；写成 `ask` 不在枚举里，整段 stdout 同样被丢）。「本会话允许」再带 `updatedPermissions`：`命令名:*`，`destination` 为 `session`。不要写成 `userSettings`。

没有 `command`、也不是联网搜索（`WebSearch`）、访问网页（`WebFetch`）或执行方式（`SwitchMode`，以及 `EnterPlanMode` / `ExitPlanMode` / `PlanAgent`）的权限请求只发 `permission_notice`，立刻回 `ask`。`CreatePlan` 也走这条。计划分两步：`SwitchMode`（执行方式建议）等三按钮卡；`CreatePlan`（这份计划要不要执行）只通知，点击通知仍跳回 IDE，选择留在 Qoder 自己的「执行」上。`WebSearch` / `WebFetch` / `SwitchMode` 等三按钮卡。允许回 `allow`，拒绝回 `deny`。始终允许只改这一项：Web 卡只把 Web 工具改成自动执行，计划卡只改计划智能体，终端卡只改终端。同一工具紧跟着的 `Notification` 在 30 秒内不再发第二条；答完卡后也不会再弹出一条横幅。超时同样回 `ask`。

`CreatePlan` 的 `allow` 会被语言服务收下（日志是 `permissionDecision=allow`，计划文件也会写出来），但 IDE 里的「执行」仍然出现。`ExecuteTool` 在 hook 返回 `allow` 后会跳过确认，工具名是 `CreatePlan` 或 `AskUserQuestion` 时这条跳过被关掉，接着进入 `waitUserConfirm`。终端命令和 `SwitchMode` 没有这条例外。计划智能体已经是「自动运行」时，这个窗口照样出现。改 stdout 的字段消不掉它。所以 `CreatePlan` 只发可点击跳转的通知，并立刻回 `ask`。

## 3. 设置页、记录文件、语言服务是三份数据

用户在设置页改终端下拉框时，页面跟着变，`User/settings.json` 也跟着变。反过来直接改 `settings.json`，页面和正在跑的进程都不变。所以 `settings.json` 只是页面同步出去的记录，不是设置页重新打开时读的那份。

| 角色 | 路径 | 字段 | 谁读它 |
|---|---|---|---|
| 设置页自己的配置 | `~/Library/Application Support/Qoder/User/app.json` | `config.chat.terminalRunMode`、`config.chat.webToolsMode`、`config.integrations.planModeRunConfig` | 设置页。打开时展平成 VS Code 配置，并同步给语言服务 |
| 页面同步出去的记录 | `~/Library/Application Support/Qoder/User/settings.json` | `app.configChatTerminalRunMode`、`app.configChatWebToolsMode`、`app.configIntegrationsPlanModeRunConfig` | 人看记录。改它不会驱动页面 |
| 语言服务正在用的值 | 套接字 `config/getGlobal`；缓存落在 `SharedClientCache/cache/app-config.json` | `terminalRunMode`、`webToolsExecutionMode`、`planModeRunConfig` | 执行端。决定这次还要不要问 |

Qoder CN 把上面路径里的 `Qoder` 换成 `QoderCN`。这三份只属于 Qoder IDE / CLI。JetBrains 插件不在这三份里，见第 7 节。

方向是单向的：

1. 设置页保存 → 内存里的 `config.chat` / `config.integrations` → 语言服务，同时写出 `app.json` 和 `settings.json`。
2. 只调语言服务 → 正在跑的进程立刻变，`app-config.json` 跟着变。`app.json` 和设置页都不变。
3. 重新打开设置页 → 读 `app.json`。里面如果还是「每次询问」，页面显示旧值，并把旧值同步回语言服务，刚才的自动执行被盖掉。之后又要在卡片上授权。

「始终允许」只改这一张卡对应的那一项。点联网搜索或访问网页不会把计划智能体改成自动运行，点终端命令也不会改 Web 和计划。语言服务和设置页用的不是同一套字符串：

| 设置页 | app.json | settings.json | 语言服务 |
|---|---|---|---|
| 终端 · 完全访问权限 | `config.chat.terminalRunMode` = `fullAccess` | `configChatTerminalRunMode` = `fullAccess` | `terminalRunMode` = `fullAccess` |
| Web 工具 · 自动执行 | `config.chat.webToolsMode` = `Auto-execute` | `configChatWebToolsMode` = `Auto-execute` | `webToolsExecutionMode` = `enabledAutoExecute` |
| 计划智能体 · 自动运行 | `config.integrations.planModeRunConfig` = `Auto-run` | `configIntegrationsPlanModeRunConfig` = `Auto-run` | `planModeRunConfig` = `autoRunInFuture` |

调用顺序：

1. `config/getGlobal` 取出整份配置。
2. `config/updateGlobal` 只改这一项的语言服务字段，其余字段原样送回。不要发缺字段的半份对象。
3. 只有终端卡再调 `config/updateGlobalTerminalRunMode`，参数 `{"terminalRunMode":"fullAccess"}`。Web 和计划不走这条。
4. 把 app.json 和 settings.json 里这一项写成设置页文案。只替换已有的字符串，文件不存在不新建，其它键不动。`questPlanModeRunConfig` 不要改。写失败不影响这次决定。

读不到 `config/getGlobal` 时，这次降级成「允许」，不写文件。读得到就先把 `allow` 交回 hook，等 hook 退出再 `config/updateGlobal` 并写文件。语言服务还停在这次 `PermissionRequest` 里时，配置更新会一直等到套接字超时，app.json 不会变，设置页重新打开仍是「每次询问」。`success` 不是 `true` 时不写文件。

`fullAccess` 的意思是所有终端命令都不再问。Web 和计划智能体改的是各自下拉框里最放开的那一档。MCP 开关不动。

## 4. 语言服务怎么调

套接字：`~/Library/Application Support/Qoder/SharedClientCache/qoder.sock`（权限 600）。帧格式是 vscode-jsonrpc：`Content-Length: N\r\n\r\n` 加 JSON。

| 方法 | 实测 |
|---|---|
| `config/getGlobal` | `result` 就是配置对象，里面有 `terminalRunMode`、`webToolsExecutionMode`、`planModeRunConfig`、`commandAllowList` |
| `config/updateGlobalTerminalRunMode` | 设置页改终端下拉框时走这条。`{"terminalRunMode":"fullAccess"}` 能改正在生效的值，回 `success: true`。它不改 `app.json`，也不改 `settings.json` |
| `config/updateGlobal` | 必须带上 `getGlobal` 的整份对象再改字段。只改一个字段时其它字段不会漂。不要发缺字段的半份对象，会把别的设置清掉。它不改设置页读的 `app.json`。Web 工具和计划智能体没有单独的更新方法，走这一条 |
| `config/appendCommandAllowList` | 多种请求体都回 `success: true`，允许列表却还是空的。不要用 |

三套下拉框的取值不要混。文件里写设置页文案，语言服务写右边那一列。`fullAccess` 不要写成 `fullaccess`。

终端（文件和语言服务用同一套）：

| 设置页文案 | 取值 |
|---|---|
| 每次询问 | `askEveryTime` |
| 黑名单 | `autoRun`（再配合 `configChatCommandDenyList`） |
| 自动审查 | `autoReview` |
| 完全访问权限 | `fullAccess` |

Web 工具：

| 设置页文案 | app.json / settings.json | 语言服务 `webToolsExecutionMode` |
|---|---|---|
| 自动执行 | `Auto-execute` | `enabledAutoExecute` |
| 每次询问 | `Ask every time` | `enabledAskEveryTime` |
| 禁用 | `Disabled` | `disabled` |

计划智能体：

| 设置页文案 | app.json / settings.json | 语言服务 `planModeRunConfig` |
|---|---|---|
| 自动运行 | `Auto-run` | `autoRunInFuture` |
| 每次询问 | `Ask every time` | `askEveryTime` |
| 禁用 | `Disabled` | `disableThisAgent` |

允许列表只在模式是 `askEveryTime` 时才会少问后续命令：命令全文等于某一项，或以「该项加一个空格」开头。`git` 命中 `git status`，不命中 `gitk`。`autoRun` 不看允许列表，只对禁用列表再问。当前按钮不再往允许列表追加命令名。

## 5. 踩过的坑

1. **把 `decision` 附在 IDE 的 stdout 上。** 卡片点了允许，IDE 日志是 `winner=none (no parsed output)`，接着仍弹出自己的选择框。IDE 只留 `permissionDecision`。
2. **只改语言服务。** 当时不同的命令都会放行，重新打开设置页仍显示「每次询问」，之后又要在卡片上授权。原因是 `User/app.json` 还是旧值，页面用它把语言服务盖了回去。`settings.json` 写成新值也挡不住，页面不读那份记录。Web 工具和计划智能体同样如此。
3. **把语言服务枚举写进 app.json。** Web 的「自动执行」在文件里是 `Auto-execute`，语言服务才是 `enabledAutoExecute`。计划智能体「自动运行」在文件里是 `Auto-run`，语言服务才是 `autoRunInFuture`。写反了，页面和执行端对不上。
4. **只改 `settings.json` 或 `app-config.json`。** 页面改配置会写文件，文件改了页面不读。执行端缓存下一次由语言服务覆盖。
5. **用 `config/appendCommandAllowList`。** 回成功，列表不变。
6. **把命令名写进 `~/.qoder/settings.json` 的 `permissions.allow`。** 永久生效，设置页无处可改。桌面版改为会话内的 `session_allow`。
7. **往允许列表追加命令名，指望它等于设置页的「始终允许」。** 那只在终端模式已经是「每次询问」时少问这一条命令。用户要的是下拉框本身变成自动执行。
8. **单测连上用户正在用的 `qoder.sock`。** `locationsForTesting != nil` 且没有 `rpcForTesting` 时，`call()` 必须返回 nil，不能落到真套接字。
9. **把 JetBrains 插件的「始终允许」写成 IDE 的 `User/app.json`。** 那两份文件是 Qoder IDE 设置页重新打开时读的。写进去会改 IDE，插件设置页却不变。插件和 IDE 各有一个 `Qoder start`。
10. **英文版和国内版插件共用 `jetbrains_plugin`。** 两个插件可以装在同一个 IntelliJ 里，bundle id 都是 IDE 的，分不开。国内版必须换成 `jetbrains_cn_plugin`，否则会写到英文版的 `~/.qoder/shared_client/qoder.sock`。已经在跑的国内版会话 state 里还是旧 product，要新开一轮才换套接字。

## 6. 代码落点

- `QoderCommandAllowList.remember`：按工具名只改一项。`config/getGlobal` 后整份 `config/updateGlobal`；终端卡再调 `config/updateGlobalTerminalRunMode`。IDE / CLI 再把这一项写进 `app.json` 和 `settings.json`。`locations(for:)` 对 `jetbrains_plugin` / `jetbrains_cn_plugin` 返回 nil，这两份文件不写。
- `QoderCommandAllowList.socketPath`：IDE / CLI 用 `~/Library/Application Support/Qoder{,CN}/SharedClientCache/qoder.sock`。插件用 `~/.qoder/shared_client/qoder.sock` 和 `~/.qoder-cn/shared_client/qodercn.sock`。
- `PermissionDecisionValue.buttonLabel`：IDE、CLI、JetBrains 插件的中间按钮是「始终允许」。桌面版仍是「本会话允许」。
- `PermissionController.decide`：IDE / CLI / JetBrains 插件走 `rememberAfterHook`；Qoder.app 只取 `sessionToken`，交给 hook 的 `remember_session_allow`。读不到 `config/getGlobal` 时这次降级成「允许」。
- `HelperTemplate` 的 `_CN_PRODUCT_MAP`：`jetbrains_plugin` → `jetbrains_cn_plugin`。`emit` 里 `decision.behavior` 仍只在 `_desktop_qoder()` 为真时附上。
- `AgentProvider.jetbrains_cn_plugin`：展示名留空，卡片仍用 host.name（IntelliJ IDEA、PyCharm）。主题色和跳转分组跟英文版插件一样，归在 Qoder。
- 测试：`Tests/BetterFocusIDETests/QoderCommandAllowListTests.swift` 的 `testJetBrainsAlwaysAllowUsesPluginServerAndSkipsIdeFiles`。

## 7. JetBrains 里的 Qoder 插件

2026-11-14。插件和 Qoder IDE 不是同一个语言服务。本机同时跑着两个 `Qoder start`：

| | 进程 | 套接字 |
|---|---|---|
| Qoder IDE | `Qoder IDE.app/.../Qoder start --workDir .../Qoder/SharedClientCache` | `~/Library/Application Support/Qoder/SharedClientCache/qoder.sock` |
| 英文版插件 | `~/.qoder/shared_client/bin/2026.1113.1/aarch64_darwin/Qoder start` | `~/.qoder/shared_client/qoder.sock` |
| 国内版插件 | `~/.qoder-cn/shared_client` 下的同一套二进制 | `~/.qoder-cn/shared_client/qodercn.sock` |

`.info.json` 里的 `ipcServerPath` 指向上面的插件套接字。国内版文件名是 `qodercn.sock`，不是 `qoder.sock`。

### 最终行为

- 中间按钮是「始终允许」。product 是 `jetbrains_plugin`。国内版安装器在启动器里 `export BETTERFOCUS_VARIANT=cn`，`_CN_PRODUCT_MAP` 把识别结果换成 `jetbrains_cn_plugin`。
- 只改这一张卡对应的那一项，枚举和 IDE 相同：终端 `terminalRunMode=fullAccess`，Web `webToolsExecutionMode=enabledAutoExecute`，计划 `planModeRunConfig=autoRunInFuture`。点 Web 卡不改计划，点终端卡不改 Web。MCP、`questPlanModeRunConfig`、浏览器开关不动。
- 先 `config/getGlobal`。读不到就降级成「允许」，不写任何文件。读得到就先把 `allow` 交回 hook，等约 1 秒（hook 每 0.5 秒看一次应答）再整份 `config/updateGlobal`，终端卡再调 `config/updateGlobalTerminalRunMode`。
- `locations(for:)` 对这两个 product 返回 nil。不写 IDE 的 `User/app.json`、`User/settings.json`，也不写 `~/.qoder/settings.json` 的 `permissions.allow`。
- stdout 仍只有 `hookEventName`、`permissionDecision`、`permissionDecisionReason`。不附 `decision.behavior`。

### 插件设置页读哪一份

IntelliJ 2026.3 的 `options/qoder_setting.xml`、`qodercn_setting.xml` 里没有 `terminalRunMode`。`~/.qoder/shared_client` 下面也没有 IDE 那种 `User/app.json`。

插件核心包 `instrumented-qoder-core` 里，设置页保存走 `LegacyGlobalConfigUpdater.saveIntegrationPolicies`：`config/updateBatch` 只带策略键，再用 `config/getGlobal` 读回来核对。策略键是 `browserRunMode`、`browserToolsRunMode`、`computerUseRunMode`、`planModeRunConfig`、`terminalRunMode`、`mcpAutoRun`、`webToolsExecutionMode`。所以插件设置页的依据是这次语言服务的 `config/getGlobal`，不是 IDE 的文件。

2026-11-14 对英文版套接字只做了读取，没有写入。`config/getGlobal` 的 `result` 有 32 个键，当时是：

| 键 | 读到的值 |
|---|---|
| `terminalRunMode` | `askEveryTime` |
| `webToolsExecutionMode` | `enabledAskEveryTime` |
| `planModeRunConfig` | `askEveryTime` |
| `questPlanModeRunConfig` | `askEveryTime` |
| `browserRunMode` | `enabledAskEveryTime` |
| `mcpAutoRun` | `disable` |

国内版套接字文件在，没有对它发请求。语言服务没起来时 `canReadConfig` 失败，这次按「允许」处理。

### 否决过的做法

- **当成 Qoder.app 的「本会话允许」。** 插件有设置页，中间按钮要改下拉框，不是只记当前会话的命令名。
- **套接字用 IDE 的 `SharedClientCache/qoder.sock`。** 那是另一个 `Qoder start`。写进去改的是 Qoder IDE，插件设置页不变。
- **把 IDE 的 `app.json` 抄一份给插件。** 插件重新打开设置页不读那份文件。写了还会在 IDE 下次打开设置时被同步回 IDE 的语言服务。
- **改用插件设置页自己的 `config/updateBatch`。** 页面发的是缺字段的策略对象。`config/updateGlobal` 在 IDE 上已经验证过：缺字段的半份对象会清掉其它设置，整份对象只改一个字段则其余不动。插件跑的是同一个 `Qoder start`，所以沿用整份 `updateGlobal`。没有在插件套接字上实际调用过 `updateBatch` 或 `updateGlobal`。
- **英文版和国内版共用一个 product。** 见第 5 节第 10 条。

### 生效前提

hook 模板改完后，应用启动会重写 `~/.qoder/hooks/betterfocus-hook.py` 和 `~/.qoder-cn/hooks/betterfocus-hook.py`。英文版 product 本来就是 `jetbrains_plugin`，Swift 侧换上新包即可。国内版要新开一轮会话：旧会话 state 里保存的还是 `jetbrains_plugin`，后续事件会继续写英文版套接字。
