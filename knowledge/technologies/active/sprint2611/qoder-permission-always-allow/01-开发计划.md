# Qoder 权限卡片「始终允许」开发计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Qoder / Qoder CN 的权限卡上点「始终允许」时，这一次回 `allow`，并把该命令名写入界面配置和执行端配置，使终端模式为「每次询问」时以后不再为同一命令弹确认。

**Architecture:** Hook 不再对权限请求立刻回 `ask`。它发出 `permission_requested` 并等待应答文件。岛上的三按钮卡已经存在：`允许` 只回 `allow`，`拒绝` 回 `deny`，`始终允许` 由 Swift 先把命令名追加进两份配置，再回 `allow`。配置写入失败时这一次降级为「允许」，不假装已经记住。不改 `terminalRunMode`。

**Tech Stack:** Swift 5.9，`HelperTemplate.swift` 内嵌的 Qoder Python hook，Qoder IDE 的两份 JSON 配置。

**日期:** 2026-11-11

---

## 已核实的事实

Qoder IDE 的 `PermissionRequest` stdout 只有 `permissionDecision`: `allow`、`deny`、`ask`。没有「始终允许」字段。`allow` / `deny` 会被采信。

持久化不在 `~/.qoder/settings.json`。那份文件只有 hook 注册。真正的放行配置有两份，内容必须一致：

| 角色 | 路径 | 允许列表字段 |
|---|---|---|
| 界面（设置页读写） | `~/Library/Application Support/Qoder/User/settings.json` | `app.configChatCommandAllowlist` |
| 执行端（决定要不要再问的进程） | `~/Library/Application Support/Qoder/SharedClientCache/cache/app-config.json` | `commandAllowList` |

Qoder CN 对应：

| 角色 | 路径 |
|---|---|
| 界面 | `~/Library/Application Support/QoderCN/User/settings.json` |
| 执行端 | `~/Library/Application Support/QoderCN/SharedClientCache/cache/app-config.json` |

安装包 `extensions/aicoding-agent/dist/extension.js` 里的匹配函数：列表按逗号拆开、去掉空白；命令全文等于某一项，或以「该项加一个空格」开头，即算命中。`git` 命中 `git status`，不命中 `gitk`。只在 `terminalRunMode == askEveryTime` 时用允许列表跳过确认。`autoRun` 不看允许列表，只对禁用列表强制再问。`fullAccess` 直接跳过。当前这台机器的 Qoder IDE 是 `autoReview`，此模式下允许列表不会减少后续确认。

执行端二进制暴露 `config/appendCommandAllowList` 与 `config/removeCommandAllowList`。直接改执行端 JSON，下次设置页保存会被界面那份盖掉。只改界面 JSON，正在跑的进程仍用旧列表。

IDE 对话框里的「始终允许」文案是「本次会话中始终允许」，和这份计划不同。本计划写的是重启后仍在的命令允许列表。

## 不做的事

- 不把 `terminalRunMode` / `configChatTerminalRunMode` 改成 `autoRun` 或 `fullAccess`。那是整类终端都不再问，不是「这一条命令」。
- 不给 Web、MCP、改文件做「始终允许」。那些走别的模式字段，本计划只处理带 `command` 的终端命令。
- 不把已在禁用列表（`commandDenyList` / `configChatCommandDenyList`，默认 `rm,mv,sudo,wget,curl,chown,remove-item`）里的命令名写进允许列表。
- 不在 `autoReview` 下承诺「以后不再问」。按钮仍可点，写入仍然发生，但只有模式日后改成 `askEveryTime` 才生效。

## 文件

- 修改 `Sources/BetterFocusIDE/Services/Installer/HelperTemplate.swift`：`run_permission` 改为等待应答。Qoder IDE 安装器使用这份模板。开工前核对 Qoder CN 安装器是否共用它；不共用则同步那一份。
- 新增 `Sources/BetterFocusIDE/Services/QoderCommandAllowList.swift`：解析命令名、合并两个 JSON、按产品选择路径。
- 修改 `Sources/BetterFocusIDE/Services/PermissionController.swift`：`decide(.allowAlways)` 在写应答文件之前调用上面的写入。
- 修改 `Sources/BetterFocusIDE/Services/AnswerDispatcher.swift`：应答 JSON 带上 `command_token`，供 hook 核对。
- 测试 `Tests/BetterFocusIDETests/QoderCommandAllowListTests.swift`。
- 改完模板后重装 Qoder hook，已安装的 `~/.qoder/hooks/betterfocus-hook.py` 不会自己变。

## 行为

1. `PermissionRequest` 且能取出终端命令时，发 `permission_requested`（现有三按钮卡），然后按提问卡的方式轮询应答文件。
2. 用户点「允许」：hook stdout `permissionDecision=allow`。
3. 用户点「拒绝」：`deny`。
4. 用户点「始终允许」：Swift 把命令名追加进两份配置，成功后应答里 `decision=always`；hook 仍回 `allow`。任一份写入失败则应答改成 `once`，hook 回 `allow`，日志记下没记住。
5. 超时或岛没在听：回 `ask`，交给 Qoder 自己的对话框。等待上限用现有的 `agentWaitLimit`，不要把工具挂满 hook 的 660 秒。
6. 没有 `command` 字段的权限请求维持现状：只发 `permission_notice`，立刻回 `ask`。

命令名取去掉空白后的第一个词。含逗号、引号、空格，或等于禁用列表中的某一项时，不提供持久化，这一次只当「允许」处理。
